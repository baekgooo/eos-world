# 용쿠 × 클로드코드 협업 보드

이 파일은 용쿠(Hermes/Telegram)와 클로드코드(Claude Code)가 서로 작업 인계, 피드백, 다음 액션을 주고받는 **공용 작업 공간**이다.

대장님이 중간 전달자로 모든 내용을 옮기지 않도록, 두 에이전트는 세션 시작/종료 때 이 파일을 먼저 확인하고 필요한 내용을 여기에 남긴다.

---

## 0. 현재 마감 목표

- 목표: 다음 주 화요일 오후까지 PDF 1차 생성 및 검수 완료
- 우선순위: 챕터 5·6·7 완성 → 전체 구조/링크 검토 → 삽화 최소 세트 생성 → PDF 조판 → PDF 검수
- 품질 기준: 완벽한 문학 퇴고보다 **출간 가능한 안정판** 우선
- 절대 지킬 것:
  - `03_sections/`가 원고 정본
  - 선택지 링크/타깃 오류 없음
  - 의미 있는 선택은 고유 결과 섹션으로 반영
  - 이안 말투와 주인공 내면선 유지
  - PDF는 깔끔하고 정돈된 인상 우선

---

## 1. 에이전트 역할

### 용쿠 / Hermes

- 대장과 텔레그램에서 실시간 회의
- 방향성 정리, 우선순위 결정 보조
- 클로드코드에게 줄 작업지시문 작성
- 클로드코드 산출물 검토 및 피드백 작성
- 작품 감정선, 문체, 분기 설계 기준 점검

### 클로드코드 / Claude Code

- 파일 직접 수정 및 대규모 작업 실행
- 섹션 원고 초안/수정
- 빌드, 링크, 프리뷰 검증
- PDF/삽화/자동화 관련 파일 작업
- 작업 후 결과와 다음 작업 제안을 이 보드에 남김

### 대장님

- 최종 판단자이자 작품 감독
- 방향 승인/거절, 취향 판단, 우선순위 결정
- 기술적 전달문 작성 부담을 지지 않는다

아직 없음.

새 요청은 아래 형식으로 추가한다.

```markdown
### [요청 ID] 작성자 → 대상 / YYYY-MM-DD

**요청:**
-

**배경:**
-

**완료 기준:**
-

**상태:** 대기 / 진행 / 완료 / 보류
```

## 6. 파일 정리 규칙

- `.hermes/COLLAB.md`: 에이전트 간 공용 보드. 세션 시작 시 가장 먼저 확인.
- `.hermes/handoffs/`: 긴 개별 인수인계 메모를 보관할 위치.
- `.hermes/compact/`: 용쿠/Hermes 컴팩트 요약 파일을 보관할 위치.
- `.hermes/archive/`: 과거 메모를 정리해 넣을 위치.

기존 `.hermes/*.md` 파일은 아직 이동하지 않는다. 이동은 별도 정리 작업으로 진행한다.

---

## 7. 클로드코드에게

클코야, 앞으로 세션 시작 시 `.hermes/COLLAB.md`를 먼저 읽고, 대장님이 전달한 용쿠 의견이나 네 작업 결과를 이 파일의 `대기 중인 요청` 또는 `피드백/응답 로그`에 짧고 명확하게 남겨줘.

작업 완료 후에는 긴 핸드오프를 별도 파일로 남겨도 되지만, 이 보드에는 반드시 한눈에 볼 수 있는 요약과 다음 액션을 남겨줘.

---

## 8. 용쿠에게

용쿠야, 대장이 클로드코드에게 전달해야 할 내용을 말하면 직접 전달문 형태로 정리하고, 중요한 지시/검토 기준은 이 파일에 남겨라.

대장이 중간 전달자로 소모되지 않게, “클코에게 붙여넣을 문장”과 “작품 판단에 필요한 요약”을 분리해서 제공한다.
